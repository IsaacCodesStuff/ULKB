# Building a kernel for the ThinkPad T440

Two builds, both meant to run on GitHub Actions (or locally):

| Build | Starts from | Use it for |
| ----- | ----------- | ---------- |
| `builds/t440-dev.yaml` | The CachyOS config the T440 runs today, trimmed to the modules it loads | The safe first kernel. It starts from a config that already boots this machine. |
| `builds/t440-minimal.yaml` | Generic `defconfig` + `configs/thinkpad/t440.config` | Learning what the hardware needs. Smaller, but more likely to miss something. |

Both build kernel **v7.2** (a release tag, so the source never moves) with the
stable kernel.org LLVM toolchain.

## One-time setup

Run these on the T440, then commit and push the results.

```bash
# 1. Save the config of the kernel you are running (the t440-dev base)
zcat /proc/config.gz > configs/thinkpad/t440-cachyos.config

# 2. Pin the toolchain checksum (downloads the toolchain once)
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
./build_kernel.sh pin-toolchain toolchains/kernel-org-llvm-23.yaml
# compare the printed sha256 with
#   https://mirrors.edge.kernel.org/pub/tools/llvm/files/sha256sums.asc

git add configs/thinkpad/t440-cachyos.config toolchains/kernel-org-llvm-23.yaml
git commit -m "Add T440 base config and pin toolchain" && git push
```

`configs/thinkpad/t440.lsmod` (the modules the T440 loads) is already in the
repo. It is what lets a build on GitHub's servers trim the config for your
laptop instead of for the runner.

## Build

On GitHub: **Actions → Build kernel → Run workflow**, type `t440-dev`, and
download the `kernel-t440-dev` artifact when it finishes. It contains:

- `bzImage`, `System.map`
- `modules.tar.zst`: the modules (nothing is installed anywhere)
- `config`: the exact `.config` used
- `build-info.json`: settings, kernel release and checksums

To build locally instead: `./build_kernel.sh t440-dev`. The kernel source is
fetched into `kernel-7.2/`, the toolchain into `build/`, and the result lands in
`out/t440-dev/dist/`, the same files the artifact contains. The folders
`out/`, `build/` and `kernel-7.2/` are generated and not committed.

## Read the config audit

After configuring, ULKB compares what the fragments asked for with what the
kernel accepted and prints every mismatch (it is in the build log):

- **(absent)**: the symbol is misspelt, was removed in this kernel, or is hidden because something it depends on is off.
- **a dependency is not enabled**: another option the symbol needs is off.
- **something else selects it**: you asked for `n`, but another option forces it on.

Add `strict: true` under `config:` to make any mismatch fail the build.

## Installing the kernel (CachyOS + GRUB)

Do this only after a build finishes. Your CachyOS kernel stays as the other
GRUB entry the whole time, so you can always boot back into it.

Your kernel goes in `/boot` (on the ext4 root). Do **not** copy anything into
the EFI partition (`/boot/efi`): it only has about 16 MB free and GRUB doesn't
need kernels there.

```bash
REL=7.2.0-ulkb-t440-dev        # the release printed in the build log / build-info.json
NAME=ulkb-t440-dev

# 1. Modules
sudo tar -I zstd -xf modules.tar.zst -C /usr
sudo depmod "$REL"

# 2. Kernel image
sudo install -m 644 bzImage "/boot/vmlinuz-$NAME"

# 3. Initramfs. Check which tool your system uses first:
pacman -Q mkinitcpio dracut
sudo mkinitcpio -k "$REL" -g "/boot/initramfs-$NAME.img"     # if mkinitcpio
# sudo dracut --kver "$REL" "/boot/initramfs-$NAME.img"      # if dracut

# 4. Add it to GRUB
sudo grub-mkconfig -o /boot/grub/grub.cfg
```

Reboot and choose the new entry under **Advanced options**. Check it with
`uname -r`.

To remove it again:

```bash
sudo rm -rf "/usr/lib/modules/$REL" "/boot/vmlinuz-$NAME" "/boot/initramfs-$NAME.img"
sudo grub-mkconfig -o /boot/grub/grub.cfg
```

### GRUB menu not showing when you boot from F12

Most likely GRUB is set to hide its menu. Look at:

```bash
grep -E 'TIMEOUT|DEFAULT|SAVEDEFAULT' /etc/default/grub
```

Then set `GRUB_TIMEOUT_STYLE=menu` and `GRUB_TIMEOUT=5` in
`/etc/default/grub` and run `sudo grub-mkconfig -o /boot/grub/grub.cfg`.
If it still skips the menu, paste the grep output and we can look further.

## Naming the kernel (setlocalversion)

You don't need to edit `scripts/setlocalversion`. ULKB writes
`CONFIG_LOCALVERSION` from `config.localversion`, with `LOCALVERSION_AUTO`
off, so the release is simply `<version>-ulkb-t440-dev`.

If you do want to change the script anyway, it is ordinary source: put the
change in `patches/` (plain `diff -u` files work as well as `git format-patch`
files) and list the directory under `patches:` in the build file.
